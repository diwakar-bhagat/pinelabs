## 3. The three routes (Pine docs: `concepts/transports`, `concepts/capabilities`)

| | **AppToApp** | **Cloud** | **PadController** |
|---|---|---|---|
| Pine's "use when" | Billing app and Pine payments app on the **same Android terminal** (our case) | Remote/backend app uploads bills to Pine cloud | Billing app on a **separate** device linked to the terminal |
| Needs on terminal | Pine payments app + **Master service** (`com.pinelabs.masterapp`, the package the SDK binds) | Terminal activated for Cloud Based Transactions | PadController app |
| Needs from Pine | Provisioned Application ID (we have UAT) | `merchant_id`, `store_id`, `client_id`, **security token** | PadController setup |
| Payment flow | App sends sale → payment screen opens → result returns to the app | App **uploads the bill** (result = Pending) → cashier opens the Pine Payments app → *Cloud Based Transaction* → customer pays → app **polls `check_status`** | Same as AppToApp, over the link |
| Receipt print from our app (`print`) | ✅ | ❌ `NotSupported` (no printer on Cloud) | ✅ |
| Barcode scan via SDK | ✅ | ❌ | ❌ |
| Cancel in-flight | ❌ (use Void) | ✅ | ❌ |
| Status check | in-memory only | ✅ real round-trip | in-memory only |
| Void | ✅ (`bank_code`; `invoice_number` "flow-dependent") | ✅ (needs the original's Plutus reference) | ✅ |
| Terminal info | ✅ (2.0.0) | ❌ | ✅ |
| Works on SN 1340055807 today | ❌ MasterApp missing | ❌ not activated, no credentials | n/a (not our setup) |

**Our recommendation:** AppToApp. It matches Pine's guidance for an on-terminal billing app, gives a single-screen
cashier flow, and lets our app print the GST bill. Cloud would work only with a manual hand-off to the Pine app on
every sale, and our app could not print.
